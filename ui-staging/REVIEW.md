# UI Redesign — Staging

All four feature drafts were REJECTED by adversarial verify. Do NOT wire them without applying fixes:

## home

- is_real: False, confidence: high
- **BLOCK**: Compile failure: HomeRedesignFeature.kt line 52 references `Switches.HOME_REDESIGN`, but no such constant exists on the `Switches` companion object. The declared switches in app/src/main/kotlin/io/github/trickhook/shadowzap/settings/Switches.kt are STATUS_DOWNLOAD, HD_IMAGES, HD_VIDEOS, NO_STATUS_TRIM, ALLOW_DEBUG, ANTI_REVOKE, SEE_EDITED, VIEW_ONCE_BYPASS, VIEW_ONCE_SAVE, MEDIA_AUTOPREVIEW, GHOST_MODE, PROPS_UNLOCK. Without a corresponding Switches constant and a DEFAULTS entry, the kotlinc build will fail (`unresolved reference: HOME_REDESIGN`).
- **BLOCK**: Feature is never registered. app/src/main/kotlin/io/github/trickhook/shadowzap/core/Features.kt lists every feature installed at boot and does not include HomeRedesignFeature. Even if the file compiled, Features.ordered() would not install it and the design intent (reskin of HomeActivity) would never run.
- **WARN**: `conversation_container` is almost certainly a RecyclerView on WA 2.26.39.11 (the chat list). Directly calling `container.addView(wrapper, 0)` on a RecyclerView throws UnsupportedOperationException("RecyclerView does not support scrolling to an absolute position. Use scrollToPosition instead")... actually it rejects addView entirely. The fallback branch (`container.addView(wrapper)`) throws again, so the whole injectSearchPill silently fails and the top-level try/catch swallows it — the search pill + filter chips will not appear even when the activity is matched. The intended surface for the chip row is the toolbar_container or a sibling of the list, not the list itself.
- **WARN**: Hook target is unreliable on WA 2.26.39.11: Activity simple name ending with 'HomeActivity' is the string that R8 renames aggressively in WhatsApp. On 2.26.39.11 the chat-list activity class is obfuscated (e.g. `com.whatsapp.HomeActivity` -> short name). The code checks `javaClass.name.endsWith("HomeActivity")` — this will miss the renamed class and the feature will never fire. The in-file comment claims resource-name based matching but the Activity matcher is still class-name based.
- **WARN**: `attachPressScale` installs an OnTouchListener on toolbar action icons that also have host OnClickListeners. Returning false propagates the event, but setting `isClickable=true` on `pill`/`chip` plus installing a touch listener without delegating to `performClick()` on ACTION_UP triggers Android Lint 'ClickableViewAccessibility' and, more importantly, animateScale() is called from ACTION_DOWN only — a cancelled gesture (e.g. parent intercepts for horizontal scroll in HorizontalScrollView) will animate down but may not receive ACTION_UP on the same view, leaving icons stuck at 0.97 scale.
- **WARN**: `findByEntryName` walks the decor view and resolves resource entry names from the activity's Resources — but for views WhatsApp inflated from fragments, especially those backed by a Compose/Material3 wrapper, `view.resources.getResourceEntryName(view.id)` on IDs allocated via View.generateViewId() throws Resources.NotFoundException. Each miss is caught, but the recursive descent re-queries resources for every View in the hierarchy on every resume + every onGlobalLayout tick before the tag is set — a measurable overhead and log flood on complex layouts.
- **WARN**: `REDESIGN_TAG_KEY` is set as `(hash and 0x00FFFFFF) or (0x7E shl 24)`. Android's setTag(int,Object) requires keys to be R.id values (defined as resources). Using a synthesized int that is not a resource id throws IllegalArgumentException: "The key must be an application-specific resource id." The try/catch suppresses the throw, but as a result the tag is never actually written — meaning onActivityResumed will re-run applyRedesign on every resume, re-injecting the search pill if `findViewWithTag(CHIP_ROW_TAG)` happens to miss (e.g. after a configuration change replaces the container).
- **WARN**: `fab` on WA 2.26.39.11 is a `com.google.android.material.floatingactionbutton.FloatingActionButton` — setting `fab.background = GradientDrawable()` is overridden by FAB's internal background drawable in onAttachedToWindow (MaterialShapeDrawable). The reskin visually survives for one layout pass then is replaced by Material's own background. Same for `elevation = 12dp`: FAB manages elevation via its own `compatElevation`. The intended neon-green circular FAB will not render as designed.
- **NIT**: Unused design tokens: Palette.DIVIDER, Palette.DANGER, Spacing.RADIUS_CARD, Spacing.RADIUS_FAB, Motion.DURATION_MEDIUM, Motion.DURATION_LONG are declared but never referenced. Harmless, but suggests the design doc is only partially implemented.
- **NIT**: `activity.dp(Spacing.ICON_SIZE)` is called four times to build the dot placeholders and search-pill end caps, but the dot ends up being a 24dp translucent circle on both ends of the pill — not the magnifier/mic icons the design (and the stock WA UI) imply. The pill will ship as two featureless grey circles with 'Ask Meta AI or Search' between them.

## chat

- is_real: False, confidence: high
- **BLOCK**: Switches.UI_CHAT_REDESIGN is undefined. settings/Switches.kt has no UI_CHAT_REDESIGN (nor UI_HOME_REDESIGN / CHAT_REDESIGN) constant — the referenced switch id does not exist anywhere in the project. ChatRedesignFeature.isEnabled() references Switches.UI_CHAT_REDESIGN at line 32, which is a hard compile error (unresolved reference). A matching const val, a DEFAULTS entry, and a settings-page toggle all need to land before this file can even be built.
- **BLOCK**: Feature is not wired into Features.ordered(). core/Features.kt lists every installable feature by name and is explicitly described in Feature.kt as the fixed install order — ChatRedesignFeature is absent. Even if the file compiles, FeatureRunner never sees it and install() never runs, so the chat screen stays stock on WA 2.26.39.11.
- **WARN**: attachPressScale clobbers WhatsApp's own OnTouchListener on critical views. View.setOnTouchListener replaces (not chains); returning false only means we don't consume the event, but WA's previously-installed listener never gets invoked at all. Composer: attachPressScaleRecursively(footer) overwrites the PTT (voice note) hold-to-record listener on R.id.voice_note_btn — recording will immediately break. Message rows: attachPressScale(bubble) overrides swipe-to-reply / long-press reaction gestures hosted on the bubble container. This is a user-visible regression on the first chat open.
- **WARN**: TAG_BUBBLE sticks across ListView convertView recycling. ListView aggressively recycles row Views; the same convertView is rebound to messages of alternating direction (incoming/outgoing). skinRow() short-circuits with `if (row.getTag(TAG_BUBBLE) === TRUE) return`, so after the first bind the row's bubble shape/color never updates — an outgoing row recycled to show an incoming message keeps the emerald #1E4A36 fill and the bottomEnd tail. Design intent (direction-aware bubbles) is missed as soon as the user scrolls.
- **WARN**: GlobalLayoutListener never deregisters when applyIfReady keeps returning false. applyIfReady() returns false both when the subtree isn't ready AND when the apply pass throws (catch block). On an activity where list/footer never materialise, or where any inner call keeps throwing, the listener fires on every layout pass for the activity's whole lifetime — a hot path in a chat screen (keyboard open/close, media download animations). Spins CPU and GC.
- **WARN**: Date-separator 'pill' is applied to the full-width row. applyPill(ctx, row, …) paints the entire row's background as the pill. In WA 2.26 the date_wrapper/system_message row is a full-width ListView row with the pill nested as a centered child — painting the row itself makes a full-screen-width rounded rectangle instead of the intended centered chip. Design intent miss, not a crash.
- **WARN**: setOnScrollListener overwrites WA's own scroll listener on the chat ListView. WhatsApp's ListView uses OnScrollListener for unread-divider positioning / fetch-more-pages triggers; replacing it with the hairline listener disables those. ListView exposes only a single scroll listener slot — no delegation here.
- **WARN**: setOnHierarchyChangeListener overwrites WA's hierarchy-change listener on the message list. ListView accepts a single OnHierarchyChangeListener; WA may install one for row-animation bookkeeping. Replacing it is silent and may affect message-insertion animations.
- **WARN**: Hairline inset arithmetic is off and uses the wrong view height. layer.setLayerInset(1, 0, target.height - max(1, dp(ctx,1)/2), 0, 0) computes the inset from target.height (toolbarHolder/toolbar) — the hairline is intended under the top bar at scroll, but the inset should be `height - hairlinePx`, not `height - max(1, dp/2)` (dp(ctx,1)/2 rounds to 0 on most densities). Hairline ends up pinned at the very bottom pixel of the bar with inconsistent thickness.
- **NIT**: `if (it is View) applyTopRoundedBackground(it as View, …)` is tautological. findByResName returns View?, so `it` after `let` is already View — the type check and cast are dead code.
- **NIT**: `className.contains(".Conversation").not()` reads awkwardly compared to `!className.contains(".Conversation")` and is redundant with the preceding endsWith check (anything ending in 'Conversation' already contains '.Conversation' if it is in that package).

## status

- is_real: False, confidence: high
- **BLOCK**: Compile error: `Switches.STATUS_REDESIGN` does not exist. In `settings/Switches.kt`, only STATUS_DOWNLOAD/HD_IMAGES/HD_VIDEOS/NO_STATUS_TRIM/ALLOW_DEBUG/ANTI_REVOKE/SEE_EDITED/VIEW_ONCE_BYPASS/VIEW_ONCE_SAVE/MEDIA_AUTOPREVIEW/GHOST_MODE/PROPS_UNLOCK are declared; there is no HOME_REDESIGN either outside the file that referenced it (HomeRedesignFeature also references `Switches.HOME_REDESIGN` which likewise is not in Switches.kt — the kernel codebase as a whole appears to be missing both redesign switches). `SwitchStore.isEnabled(env, Switches.STATUS_REDESIGN)` is an unresolved reference → the module will fail compilation of `app`.
- **BLOCK**: Even if the compile error were fixed, `StatusRedesignFeature` is not referenced from `core/Features.kt::ordered()`. The install pipeline iterates only `Features.ordered()`, so the object is dead code — nothing calls `install(ctx)`, so no activity callbacks ever get registered and nothing is re-skinned.
- **WARN**: The comment on `onActivityStarted` claims that re-skinning on start handles a tab switch back to the Updates fragment, but tab/fragment switches inside WhatsApp's HomeActivity do not trigger `Activity.onStart` — the activity remains STARTED/RESUMED across the whole tab bar. So the stated reason for the extra pass is false; the pass only helps if the activity is stopped and restarted (app backgrounded).
- **WARN**: `installRowSkin` calls `list.setOnHierarchyChangeListener(...)`, which unconditionally replaces whatever listener may already be set. If WhatsApp (or a RecyclerView-based parent utility) has an existing listener on the Updates RecyclerView, our skin silently breaks it. Should save and chain the previous listener instead.
- **WARN**: `skinRow` installs `OnTouchListener` on every attached row via `applyPressScale`. On RecyclerView rows this overrides any OnTouchListener WhatsApp may already have set (e.g., for row-level press ripples or custom drag handling). OnClickListener still fires because we return false, but any WA touch-level handling is lost.
- **WARN**: The press-scale `ValueAnimator` is created new on every ACTION_DOWN/UP without cancelling the previous one; rapid press-release-press stacks animators and causes scale jitter.
- **WARN**: `looksLikeTitle` compares `tv.textSize` (px) against `density * 15f`. For a 15-sp title that's actually `scaledDensity * 15f`; using plain density means the threshold is wrong when the user has a non-default font scale, misclassifying titles as subtext (or vice versa).
- **WARN**: `avatar.foreground = AvatarRing(...)` relies on View#setForeground being available for arbitrary Views (API 23+). If the module's `minSdkVersion` is below 23, this throws NoSuchMethodError on the first unseen status row. Needs an SDK gate or FrameLayout-only path.
- **WARN**: `findAvatar` scans every ImageView in the row and keeps the largest within a 40–80 dp box. The `width`/`height` fields are measured sizes, which are zero before layout. On the first resumed pass (before a layout pass completes) the finder returns `null` and the ring never gets installed; no retry on OnPreDraw/OnGlobalLayout, unlike `HomeRedesignFeature`'s scheduleApply.
- **WARN**: `row.setBackgroundColor(Tokens.BG)` on every row destroys WhatsApp's own ripple/selectable background (`?selectableItemBackground`). Visual press feedback for list items is now purely the scale animation; long-press selection, highlight-on-reply, and other WA states lose their visible cue.
- **WARN**: `skinFab` resizes `lp.width`/`lp.height` to fixed dp values. If the FAB's layout params are `WRAP_CONTENT` (-2) or `MATCH_PARENT` (-1), the guard `lp.width > 0 && lp.height > 0` skips the resize — but for a FAB that was explicitly sized in dp, writing new fixed sizes without preserving margin/anchor fields of a CoordinatorLayout.LayoutParams can detach it from its CoordinatorLayout behavior (anchoring to bottom nav, hide-on-scroll). FAB can snap to the wrong place.
- **WARN**: The playback Reply bar detector matches TextViews whose text `startsWith("Reply", ignoreCase = true)` — WhatsApp localises this string, so the overlay only kicks in on English builds. On a `pt`/`es`/`fr` device the reply bar is left unstyled.
- **WARN**: `SECTION_LABELS` is English-only too ("Status", "Updates", "Recent updates", …). All header-styling branches are no-ops on any non-English locale, so the section headers fall through to the default subtext styling (`textSize = 13sp`, tertiary color), looking actively broken.
- **NIT**: `DURATION_MEDIUM`, `DURATION_LONG`, `ACCENT_PRESSED`, `SURFACE_ELEVATED`, `DANGER`, `TEXT_SECONDARY` are declared but never used — unused-symbol noise in a feature advertised as a design system.
- **NIT**: `AvatarRing.setColorFilter(cf: ColorFilter?)` overrides a nullable-parameter method but the Drawable superclass declares `setColorFilter(colorFilter: ColorFilter?)` — fine — however `getOpacity()` is deprecated and the suppression is correct; still, consider overriding `getAlpha()` for consistency with modern Drawable contract.
- **NIT**: `SKIN_TAG_KEY = 0x535A5100` is used with `View#setTag(int, Object)`. The upper byte (0x53) is well above the API-required 0x02 threshold, so it won't throw, but Android's docs ask for an application-declared resource id to guarantee uniqueness; another module using the same magic will collide.

## settings

- is_real: False, confidence: medium
- **BLOCK**: TAG_KEY_PRESS and TAG_KEY_ANIM are built as `hashCode() and 0x00FFFFFF`, which zeros the top byte. Android's View.setTag(int, Object) throws IllegalArgumentException when `(key >>> 24) < 2`. The sibling HomeRedesignFeature deliberately ORs `(0x7E shl 24)` to pass this check; this file does not. Every `row.setTag(TAG_KEY_PRESS, true)` and `v.setTag(TAG_KEY_ANIM, anim)` will throw, caught by the surrounding try/catch, so the press-scale animation and the de-duplication guard both silently fail. The 'rows feel pressable' design intent never ships.
- **BLOCK**: SettingsRedesignFeature is not registered in `Features.ordered()` (app/src/main/kotlin/io/github/trickhook/shadowzap/core/Features.kt). The kernel only installs features listed there, so the file compiles but is dead code until the list is updated. The review message does not include that change.
- **WARN**: `installChildWatcher` calls `host.setOnHierarchyChangeListener(...)` on the stock settings container. This API accepts a single listener and silently replaces any existing one WhatsApp may have attached (e.g., for its RecyclerView-equivalent linear container, async view-stub inflation callbacks, or adapter diffing). On WA 2.26.39.11 this is a plausible way to break scroll/row behavior without a crash.
- **WARN**: `installPressScale` calls `row.setOnTouchListener { ... }` on every styled row. WDSListItem / list rows on WA often ship their own OnTouchListener for ripple hotspot or long-press affordances; this unconditionally replaces it. The returned `false` lets click handlers still fire but any touch-listener-driven behavior (haptics, custom gestures) is lost.
- **WARN**: The reskin targets `me_tab_appbar_layout`, `me_tab_motion_layout`, `me_tab_cover_photo`, `me_tab_profile_info_photo`, `me_tab_profile_info_name`, `me_tab_username`, `me_tab_about_bubble` — these are the Home activity's Me-tab resource entries. The hook only engages when the activity simple-name ends with `SettingsTabActivity`. If on WA 2.26.39.11 Settings is a stand-alone activity rather than the Me-tab fragment hosted inside Home, none of these entries will resolve and the header reskin becomes a no-op (the activity-name suffix is also not verified against a confirmed WA 2.26.39.11 dump in this review).
- **WARN**: `paintAppBar` uses `tintChildTexts(search as? ViewGroup ?: return, Palette.TEXT_PRIMARY, Palette.TEXT_SECONDARY)` — the `?: return` exits the entire function body (not just the branch) when `search` is non-null but not a ViewGroup, skipping the subsequent `tintChildImages(search, Palette.TEXT_SECONDARY)` call and any later statements in the same try block. Same shape in `paintToolbar`, where `tintChildTexts(toolbar as? ViewGroup ?: return, ...)` short-circuits before `tintChildImages(toolbar, Palette.TEXT_PRIMARY)`.
- **WARN**: `styleRow` mutates `row.layoutParams` (margins, height) on every pass, which calls requestLayout. The ViewTreeObserver.OnGlobalLayoutListener re-fires on every subsequent layout; the top-level `applied[activity]` guard prevents a full re-apply, but `reskinRowsOnly` + `installChildWatcher`'s `host.post { styleRows(...) }` can still re-enter styleRows during the next layout and keep reassigning margins/background, producing visible jank or in pathological cases a tight relayout loop.
- **WARN**: `isRowCandidate` requires `v.isClickable == true` to treat a child as a row. WA list rows are often inflated with click handled by a child or by programmatic click on first measure; a row whose clickable flag is set lazily after inflation will be excluded on the first pass and never grouped (the `applied[activity] == true` branch calls `reskinRowsOnly`, which re-runs grouping, but a row that was already styled with the wrong top/bottom radii won't be corrected because `styleRows` doesn't track prior grouping).
- **WARN**: `findLogoutMarker` lowercases row text and matches `startsWith("log out")` — the ES/PT WhatsApp strings (`Cerrar sesión`, `Sair`) will not match, so the row keeps the emerald accent instead of the DANGER tint. The design intent of surfacing the destructive action for locale != en will not land.
- **NIT**: `installPressScale` stores the previous focus listener via `row.getOnFocusChangeListener()` into `existing`, then unconditionally reassigns it back with `existing?.let { base.onFocusChangeListener = it }`. This has no effect — the focus listener was never touched by the function. The comment and code imply a defense that is a no-op.
- **NIT**: Comment inside `paintToolbar` says 'WDSToolbar paints its own divider; mask it by overlaying a background strip in #0F1512 — a 0-height divider isn't exposed in a portable way, so we just rely on background matching the body.' No overlay is actually added, so a visible toolbar divider on WDSToolbar builds will remain.
